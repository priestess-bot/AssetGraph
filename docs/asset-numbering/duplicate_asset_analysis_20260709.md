# 麦兔素材重复原因分析

记录时间：2026-07-09

本分析基于 `D:/AssetGraph/素材` 当前媒体文件的 SHA256 哈希检测，以及归档中的 `麦兔素材清单.json`、`待下载任务清单.json`、数字分身详情和模板详情进行追溯。

## 结论总览

当前检测到 8 组完全重复素材。重复不是因为文件扫描错误，而是麦兔业务里同一个物理素材会以不同“业务角色”出现，下载脚本又按不同角色分别落盘，导致同一 URL/同一文件被保存到多个目录或多个文件名下。

重复来源主要有三类：

1. 数字分身成品和模特源数据共享同一封面/预览视频。
2. 麦兔素材库中存在不同 material_id 指向同一个 URL。
3. 音色或模板素材复用同一默认封面/底图。

因此重复素材不应简单粗暴删除。更合理做法是：

- 保留一个物理文件作为主文件；
- 在 AssetGraph 数据库里保留多个业务引用/别名；
- Browser use 选择素材时按业务角色选，不按物理重复文件选。


```text

```

原因：

- `37200_张裕定制形象260519` 是数字分身成品。

| 路径 | 业务角色 |
|---|---|
| 数字分身成品/37200_张裕定制形象260519.png | 数字分身成品封面 |
| 数字分身成品/37200.../cover.png | 数字分身详情封面 |
| 模特/7717_Y26定制/cover_url.png | 模特封面 |
| 模特/7717.../分段封面/00...cover.png | 模特训练片段第 0 段封面 |

建议：

- 物理文件可只保留 1 份。
- 数据库保留 4 条引用关系，分别标注为成品封面、详情封面、模特封面、分段封面。

## 为什么会这样

重复素材出现的根本原因是：

```text
麦兔的“业务对象”不是严格一文件一素材。
```

同一个物理文件可能同时承担多个角色：

- 数字分身成品封面
- 模特封面
- 训练片段封面
- 列表预览图
- 详情页预览图
- 音色默认封面
- 模板内图层素材
- 素材库独立素材

下载脚本为了完整还原麦兔结构，按业务入口分别下载，因此会把同一个 URL 存到多个位置。

---

## 对 AssetGraph 的建议

不要把“文件路径”当作唯一资产。应区分：

```text
PhysicalAsset：物理文件，按 sha256 去重
MaituMaterialAlias：麦兔素材记录/业务别名，保存 material_id、name、url、maitu_type、用途
AssetRoleBinding：一个物理素材在不同业务对象中的角色
```

建议数据关系：

```text
PhysicalAsset(sha256, file_path, media_kind)
  <- MaituMaterialAlias(material_id, source_url, maitu_name)
  <- AssetRoleBinding(role, maitu_type, subject, scene/layer/entity)
```

这样 Browser use 选素材时可以按业务需求找：

```text
maitu_type=装饰 AND browser_usage=商品贴片 AND subject=品酒大师MASTER
```

而不是被重复文件干扰。

## 去重策略建议

### 短期文件夹整理

建议：

1. 先保留重复素材，不急着删除。
2. 编号清单里标记重复组。
3. 如果要清理磁盘，再把重复副本移动到 `_重复素材归档`，不要直接删除。

### 长期 AssetGraph 入库

建议：

1. 入库时计算 SHA256。
2. 如果 SHA256 已存在，不新增 PhysicalAsset。
3. 新增一条别名/角色绑定。
4. Browser use 查询时返回业务别名，但落地文件路径指向同一个主文件。
