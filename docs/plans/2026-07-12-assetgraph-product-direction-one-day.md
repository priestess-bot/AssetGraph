# AssetGraph 产品主线一日冲刺计划

> **For Hermes:** 后续执行时使用 `subagent-driven-development`，按小时块推进；涉及真实麦兔 UI 的步骤必须 headed、逐步回读、禁止正式开播。

**Goal:** 用一天打通一条可演示、可复现、可审计的真实主链路：`合格剧本 → 场景 → 素材需求 → AssetGraph 真实选材/缺口 → 麦兔绑定 → 内容驱动布局 → BuildPlan → 新建麦兔直播间草稿 → 回读校准 → 结果沉淀`。

**Architecture:** AssetGraph 后端负责事实、素材检索、缺口判断、布局和 BuildPlan；Browser-use Worker 只执行已经通过安全门禁的小步 UI 操作，并在每步后回读真实页面。`liveRoomId=38336`「张裕夏日主题」只作为只读质量基线和布局参考，不作为被修改对象，也不作为复制模板主轴。

**Tech Stack:** FastAPI、PostgreSQL、AssetGraph 素材库、Qwen3 embedding/reranker、Browser-use CLI、麦兔网页、pytest、Ruff。

---

## 一、这一天在项目大方向上的唯一主题

不是继续增加零散 API，也不是继续扩充模板复制能力，而是把现有大量能力压缩成一个用户能看懂的产品结果：

> 给 AssetGraph 一份基于已核验事实的直播剧本，系统能够解释每个场景需要什么素材、从真实素材库选择了什么、还缺什么、为什么这样布局，并在麦兔中新建一个可审阅直播间草稿；系统能用截图、DOM/API 回读和执行记录证明搭建结果，且绝不点击正式开播。

主路径固定为：

```text
已核验商品事实
  → 24 小时循环纯口播剧本与质量门禁
  → ScriptScene
  → ScriptAssetNeed
  → AssetSelection / GapReport
  → 麦兔真实素材绑定
  → Content-driven Layout
  → Script-layout BuildPlan
  → Headed Browser-use 新建草稿
  → 默认第 1 场景直接填充，第 2 场景起才新建
  → 坐标/脚本/素材权威回读
  → 截图、MT-EXEC、失败类型、可复用规则沉淀
```

## 二、当日验收标准

一天结束时至少形成一个“黄金样板运行”，满足：

1. 使用一组仓库内已有、可核验的商品事实，不臆造商品总数、价格、库存、赠品或促销。
2. Stage 0 剧本质量门禁通过；主播口播与内部核验备注物理分离；没有时段、倒计时、告别、重复凑时长等 24 小时循环禁项。
3. 每个场景都有明确的素材需求、真实选中素材或明确缺口；模板预览 `MT-TPL-*` 不作为实际图层素材。
4. 高优先级素材缺失时自动阻断，不拿无关素材硬填；若缺口可在当天补齐，则通过真实麦兔素材上传/查重/回读完成绑定。
5. BuildPlan 使用内容驱动操作：`fill_default_scene`、`create_scene`、`insert_asset_layer`、`position_asset_layer`、`write_script`、`verify_scene`、`save_draft`。
6. 新建独立麦兔直播间草稿，不修改参考直播间 38336；第 1 场景使用直播间自带默认场景，不重复创建。
7. Browser-use 使用可见 headed 界面；每个位置调整都有目标坐标和实际坐标回读，不能凭感觉拖动。
8. 至少完成“默认场景 + 第 2 场景”的真实搭建，或在安全门禁阻断时产出完整阻断证据与可恢复计划。
9. 保存草稿和执行证据，但 `ready_for_go_live=false`，不点击“正式开播”。
10. Backend/Worker 相关测试、Ruff、diff check 通过；独立审查无 P0/P1 才将当天成果标记为完成。

## 三、小时级工作安排（完整工作日 09:00–20:00）

### 09:00–10:00｜确定黄金样板与安全起点

**产品目标：** 把这一天收敛到一个真实可演示案例，禁止同时铺开多个直播间或多个商品方向。

**工作内容：**
- 从仓库已有事实数据/测试样例中选择一组事实完整的商品输入；缺失的促销、库存、价格字段保持未核验，不进入口播。
- 明确目标输出为“新直播间草稿”，参考直播间 `38336` 仅只读参考。
- 固定首版仅做 2 个可验证场景：默认场景 + 新建第 2 场景；复杂多场景扩展不进入当天主目标。
- 检查当前 Phase D 安全门禁是否已达到可进行真实 mutation 的条件：PostgreSQL checkpoint 回归、Worker 全量、Ruff、固定 hash 终审无 P0/P1。

**小时产物：**
- `tmp/golden-run/verified-product-facts.json`
- `tmp/golden-run/acceptance-checklist.md`
- 明确的 go/no-go 结论。

**止损门：** Phase D 未通过无 P0/P1 终审时，后续仍可完成剧本、选材、布局、BuildPlan 和 in-memory dry-run，但不得执行真实麦兔写操作。

### 10:00–11:00｜生成合格剧本，建立内容源头

**产品目标：** 让后续所有场景、素材需求和脚本写入都来自同一份合格生成稿。

**工作内容：**
- 调用 `POST /api/maitu/livestream-script-drafts` 或聚合管线生成 Stage 0 剧本。
- 检查纯口播、事实归属、促销核验、24 小时循环、去重、无凑时长等质量报告。
- 若质量失败，只修复事实输入或生成规则；不手工在下游 BuildPlan 中偷偷替换脚本。
- 固定 `sections[].script` 为后续 `write_script.script_text` 的唯一权威来源。

**小时产物：**
- `tmp/golden-run/script-draft.json`
- 一份通过的质量报告；若不通过，输出明确 `blocked_script_quality` 原因。

**验收：** 所有会写入麦兔的操作都能追溯到通过门禁的剧本段落。

### 11:00–12:00｜从剧本提取场景和素材需求

**产品目标：** 证明 AssetGraph 的核心是“理解内容后找素材”，而不是“先挑模板再硬套剧本”。

**工作内容：**
- 将剧本拆成两个当天目标场景，明确 `scene_goal`、关键词和脚本。
- 调用/验证 `script-asset-needs`，生成背景、数字人、商品贴片、辅助视觉、促销贴片和脚本文本需求。
- 检查泛词误召回：不能因为“红酒/葡萄酒/干红”等通用词就推导出不相关商品素材。
- 对过于模糊的需求标记 `manual_review`，不凭空创造具体素材要求。

**小时产物：**
- `tmp/golden-run/script-scenes.json`
- `tmp/golden-run/asset-needs.json`

**验收：** 每个素材需求都能回答“来自哪句剧本、服务什么场景目标、优先级是什么”。

### 12:00–13:00｜真实素材检索、选择与缺口报告

**产品目标：** 用 AssetGraph 真实数据库和检索服务完成选材，而不是使用 mock 或模板预览充数。

**工作内容：**
- 先按 `required_category`、`accepted_asset_types` 和麦兔原生类型硬过滤，再用关键词、embedding/reranker 排序。
- 返回 `AG-*` 全局编号、麦兔/本地友好编号、匹配分和匹配原因。
- 排除 `MT-TPL-*` 模板预览成为直接图层素材。
- 生成聚合缺口报告，按 `need_type + required_category` 合并重复缺口。

**小时产物：**
- `tmp/golden-run/asset-selections.json`
- `tmp/golden-run/asset-gap-report.json`

**验收：** 高优先级缺口必须 `blocks_auto_build=true`；不能选无关素材让流程“看起来成功”。

### 13:00–14:00｜补齐或权威绑定麦兔素材

**产品目标：** 把“AssetGraph 里有文件”升级为“麦兔里确实可被找到和插入”。

**工作内容：**
- 对每个选中素材检查现有麦兔绑定、类型、material ID、URL、数字人 speaker/image ID 和本地文件。
- 已绑定素材通过麦兔权威 inventory 重新验证，不盲信旧数据库字段。
- 未绑定但本地已有的普通图片/视频，走可见素材管理 UI 上传、查重、唯一回读并通过 API 写回绑定。
- 数字人或不支持自动上传的类型保持 `manual_required`，不把训练视频当普通视频替代。

**小时产物：**
- `tmp/golden-run/material-resolution-report.json`
- 可执行素材清单或明确的阻断清单。

**验收：** 所有进入真实 BuildPlan 的素材都具有唯一、类型兼容、可回读的麦兔身份。

### 14:00–15:00｜生成内容驱动布局

**产品目标：** 让系统根据场景内容和素材角色生成可测量布局，同时以 38336 为最低质量参考，而不是直接复制它。

**工作内容：**
- 背景全画布；数字人为主播主体；商品图/视频为焦点；贴片作为覆盖层；脚本文本进入脚本面板。
- 参考 38336 的视觉层级、坐标家族和脚本组织方式，检查新布局是否达到最低可读性。
- 输出明确 `x/y/width/height/z-index/fit`，加入安全区、遮挡和画布边界检查。
- 缺素材时使用 strict 阻断；只有人工审阅场景才允许 placeholder 计划，且 `can_execute=false`。

**小时产物：**
- `tmp/golden-run/layout-plan.json`
- 两场景布局预览摘要和坐标表。

**验收：** 每个图层都有素材身份、业务角色、几何目标和验收容差。

### 15:00–16:00｜生成并审计 BuildPlan

**产品目标：** 把布局变成 Worker 能安全执行、能暂停、能恢复的确定性操作序列。

**工作内容：**
- 第 1 场景必须使用 `fill_default_scene`；第 2 场景才使用 `create_scene`。
- 每个素材生成 `insert_asset_layer + position_asset_layer`。
- 每个场景生成 `write_script + verify_scene`。
- 末尾只有 `save_draft`，不允许 go-live 操作。
- 运行 BuildPlan dry-run，检查 operation 数量、依赖顺序、目标 liveRoom 绑定、checkpoint fingerprint 和所有安全门禁。

**小时产物：**
- 持久化的 `MT-BUILD-*`
- `tmp/golden-run/build-plan-review.md`

**验收：** BuildPlan 全部来源可追溯、素材无缺口、目标为新草稿、`ready_for_go_live=false`。

### 16:00–17:00｜Headed 预检并新建独立直播间草稿

**产品目标：** 从规划进入真实麦兔现场，但只做最小、可验证、可恢复的动作。

**工作内容：**
- 启动/复用可信 named Browser-use session 和 loopback CDP，保持可见 headed 浏览器。
- 确认登录态、工作环境、非直播状态、页面 origin 和 transport。
- 新建独立直播间草稿；不进入或修改 38336。
- 回读新 `liveRoomId`、标题、默认场景和未开播状态，并将 BuildPlan 绑定到该目标。

**小时产物：**
- 新草稿 `liveRoomId`
- 创建前后截图/DOM 状态
- preflight 与创建 checkpoint 证据。

**止损门：** 页面状态、登录、目标房间、lease、checkpoint 或 authority 任一不确定，立即停止，不重放创建动作。

### 17:00–18:00｜填充默认第 1 场景

**产品目标：** 完成一个真正可看的首场景，而不是只证明“按钮能点”。

**工作内容：**
- 直接重命名并填充系统自带默认场景，禁止再创建一个“第 1 场景”。
- 插入已绑定的背景、数字人、商品/辅助视觉；写入该场景的权威剧本段落。
- 按布局坐标定位，每一步后回读图层 identity、类型、坐标和脚本文本。
- 若实际坐标超出容差，生成一次明确的补偿调整；不盲目连续拖动。

**小时产物：**
- 第 1 场景 before/after 截图
- 实际几何回读
- 每个 operation 的 checkpoint/evidence。

**验收：** 场景素材、脚本和几何均与计划一致；任何不确定副作用进入 reconcile，不盲重放。

### 18:00–19:00｜创建并填充第 2 场景

**产品目标：** 证明 AssetGraph 能处理真正的多场景，而不是单场景演示。

**工作内容：**
- 新建第 2 场景并权威回读新 clip/scene ID。
- 插入该场景自己的素材和脚本，不复用第 1 场景的错误上下文。
- 完成坐标定位、脚本写入和场景级验证。
- 切换两场景复查，确认图层没有串场、脚本没有写错 clip。

**小时产物：**
- 第 2 场景截图、DOM/API 回读
- 两场景对照表。

**验收：** 两场景 identity、素材、脚本和几何彼此隔离且可追溯。

### 19:00–20:00｜闭环验证、结果回写与下一轮输入

**产品目标：** 把一次 UI 搭建变成 AssetGraph 可学习、可复现、可继续迭代的系统资产。

**工作内容：**
- 保存草稿；再次确认未点击正式开播、`ready_for_go_live=false`。
- 回写 `MT-EXEC-*`、operation results、截图/DOM 证据、失败类型和人工事项。
- 将计划几何与实际几何做误差对比，整理成功动作和失败/补偿动作。
- 运行 Backend/Worker 相关测试、Ruff、diff check 和独立 P0/P1 审查。
- 更新 README/架构文档中的真实黄金路径；只沉淀通用规则，不把本次临时 ID 当长期配置。

**小时产物：**
- `tmp/golden-run/final-run-report.md`
- 一条完整 `MT-EXEC-*` 记录
- 截图/回读证据索引
- 第二天的三项优先改进列表。

**最终验收：**
- 成功路径：两个真实场景草稿可见、可回读、可复现、未开播。
- 阻断路径：如果真实执行未完成，也必须有明确阻断点、证据、可恢复 checkpoint 和下一步，而不是“看起来可能成功”。

## 四、当天明确不做

- 不修改参考直播间 `38336`。
- 不点击“正式开播”。
- 不把模板匹配当主路径，不复制模板预览为图层。
- 不扩展到完整 24 小时几十场景；当天只做 2 场景黄金样板。
- 不做前端大改版、全新向量数据库或无关基础设施升级。
- 不为通过演示而放宽素材缺口、鉴权、checkpoint、readback 或人工复核门禁。
- 不同时追多个真实直播间，避免失去可复现性。

## 五、风险与动态调度规则

1. **安全终审未通过：** 保留 09:00–16:00 的内容/选材/布局/BuildPlan工作；16:00 后改为 in-memory 和只读 headed preflight，不做真实 mutation。
2. **关键素材缺失：** 13:00–14:00 优先补绑定；仍缺则 strict 阻断，不拿模板预览或无关商品图替代。
3. **麦兔 UI 选择器变化：** 保留截图和 DOM，记录 `selector_changed`，停止当前 mutation；不在未知状态下重复点击。
4. **创建动作结果不确定：** 进入 reconcile，先按名称/时间/目标身份权威查找是否已创建，不能再次点击“新建”。
5. **单步耗时超过 1 小时：** 缩小当天样板范围，但不降低安全门禁；优先保证“默认场景完整 + 第 2 场景可验证骨架”。

## 六、一天结束后项目应该处于什么位置

这一天的价值不是多写多少代码，而是让 AssetGraph 从“能力很多的后端与 Worker 集合”前进一步，成为一个能回答以下问题的产品：

- 为什么这段剧本需要这些素材？
- 真实素材库里选了什么，为什么选它？
- 缺什么，为什么不能继续？
- 新直播间每个场景应该怎么布局？
- 麦兔实际执行后是否真的和计划一致？
- 如果失败，下一次如何安全恢复而不重复副作用？

达到这个位置后，第二天再扩展到更多场景、自然语言坐标微调、视觉质量评分和 24 小时循环编排，才是顺序正确的产品推进。
