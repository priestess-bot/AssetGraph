## 成熟模式复盘

### Shopify 资源管理模式

素材、模板、知识和项目采用可扫描的资源列表、紧凑筛选、批量操作和按需详情检查器。保留了 Shopify 类后台“列表先行、操作就近、详情渐进展开”的优点，同时避免把每个对象都做成独立技术表单。当前密度适合重复运营操作，主动作不会与筛选竞争。

### Figma 编辑器模式

直播间工作区采用左侧场景/图层、中央真实比例画布、右侧属性、底部保存与写入动作。选择对象后属性与画布同步，画布不会因内容变化重新排版。借鉴的是稳定空间分工和直接操控，不复制 Figma 的专业设计术语或高密度工具栏。

### Premiere 工作区模式

成片工作区将播放器、镜头属性和画面/字幕/音频轨道放在同一首屏，当前镜头在预览、属性和时间轴中保持一致。制作进度与质检放入独立标签，避免占用日常剪辑空间。当前版本只呈现业务需要的剪辑能力，没有引入专业软件的复杂轨道控制。

### Stripe 分析模式

概览和运营分析先显示时间/指标/样本范围，再展示趋势或排行，并在结果附近标明证据等级和“关联不代表因果”的边界。数值、口径和下钻动作比装饰图表优先，异常使用影响与下一步表达，不暴露告警编码。

## 最终泄漏扫描

静态门禁 `npm run check:product-copy` 使用 TypeScript AST 扫描 12 个正式页面，禁止可见的 `<pre>`、`<code>`、`JSON.stringify`、指纹、Schema、错误码和 trace 字段。运行时审计再扫描 20 个首屏的可见文本，内部令牌命中数均为 0。未知英文枚举通过集中词典回退为中文业务兜底，不原样回显。

## 仍需外部验收

以下事项需要真实外部环境或业务判断，不能由本地固定数据替代：

1. 使用一份获授权的真实直播录屏完成上传、解析、转写修正、单一来源模板清洗和重新打开验证。
2. 使用获授权的麦兔测试账号、空白且未开播的直播间和已批准素材，验证草稿写入、刷新回读与人工交接；正式开播始终保持禁用。
3. 使用真实运营导出文件完成字段确认、问题修复、场次关联和表现分析，核对业务口径是否易懂。
4. 由未参与实现的直播运营人员完成素材、模板、项目、直播间、成片、运营和再生产的串联任务，记录耗时、回退、误操作和求助点。
5. 由产品负责人在目标显示器上完成最终视觉与人机工效验收，确认信息密度、业务用语和关键动作优先级。

输入要求和真用户任务脚本继续使用 `docs/evidence/customer-v1-v1-external-acceptance-inputs.md`。其中任何账号、令牌或个人数据不得写入仓库。
