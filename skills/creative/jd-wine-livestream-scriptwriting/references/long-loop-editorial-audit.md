# 长循环直播稿整篇文笔审校

用于30分钟及以上、多SKU、24小时循环口播。重点不是逐句润色，而是消除“每段都合格，整篇却很奇怪”的拼接感。

## 审校顺序

### 1. 先冻结主播声音

用一句话写出主播人格，例如：

> 懂酒但不卖弄，判断直接，愿意替观众缩小选择。

整篇统一检查称呼、判断力度、专业词密度和促单语气。若同一稿件一会儿像老师、一会儿像客服、一会儿像叫卖主播，先统一声音，再改句子。

### 2. 去掉标题后连续阅读

不能只随机抽段。至少选择两个跨SKU连续片段，每段约三分钟口播量，完整读过产品转场。检查：

- 新产品是否每次都从零开始；
- 上一款留下的选择问题是否被下一款承接；
- CTA是否突然打断语气；
- 句子是否连续过短、节拍过齐；
- 段落是否像独立卡片拼接。

### 3. 做解释必要性删减

常见名词直接使用。只有影响购买、容易误解、构成SKU差异或来自观众提问时才解释。

删除测试：

> 去掉这句解释，观众还能不能判断适不适合自己？

能，就删。不能，再用一句话说清。每款通常保留0–2个必要解释，不靠科普填时长。

### 4. 时长服从信息密度

删掉科普后时长不足，先检查是否还有遗漏的、真实影响购买的内容：

- SKU之间尚未讲清的差异；
- 自饮、宴请、礼赠中尚未覆盖的具体判断；
- 尚未处理的购买异议；
- 已核验但尚未使用的福利和CTA；
- 必要且不重复的转场。

这些内容本来就应该出现，才能补入；不能为了达到分钟数主动制造新段落。若没有新的事实、差异、异议、场景、利益点或动作，停止扩写，并标记 `insufficient_verified_material_for_target_duration`。

不得把已经删除的定义、重复香气、醒酒储存常识、规格提醒或空泛场景重新塞回去。

## 范围、去重与从零起稿

### 不把覆盖商品当成全量商品

口播讲到的 SKU 只是脚本范围。未拿到完整商品清单时，不得说“直播间这八款、全部商品、就这几款、把八款缩到两款”。直接比较产品名或说“当前讲到的产品”。

运营稿分别记录：

```yaml
featured_skus: []
catalog_total_verified: false
verified_catalog_total: null
```

### 做语义去重

建立信息所有权账本，每条核心卖点、场景、异议和比较只安排一个主讲位置。后文回调必须增加新比较、新动作或必要上下文。

逐段问：

> 删除这一段，观众是否仍然得到完全相同的购买判断？

若答案为是，删除。总结只压缩决策，不逐款复述。

### 反馈重写从空白开始

用户要求重写时：

1. 新建空白文件和新结构；
2. 事实只取自原始资料和已核验来源；
3. 旧稿只列失败模式和禁用表达；
4. 不复制旧稿再替换句子；
5. 成稿后做长短语重合审计。

除产品名、规格、法定提示和不可改写事实外，非必要长句重合应为零。

## 五步交付审计

### 1. 商品范围扫描

先确认完整商品清单是否经过运营核验。未核验时，扫描并删除以下语义：

```text
直播间这N款|直播间一共N款|全场N款|把N款缩到M款|所有商品|全部商品|就这几款
```

脚本覆盖数量只能留在运营稿，不能被主播说成直播间库存结构。

### 2. 信息所有权检查

为每个核心卖点、比较、异议、场景和CTA标记唯一主讲段。后文出现同一信息时，必须注明新增功能：`new_comparison`、`new_action`、`new_viewer_context` 或 `loop_reentry`。没有新增功能就删除。

### 3. 段落删除测试

逐段提问：

> 删除本段后，观众是否损失一个新的事实、差异、异议答案、具体场景、已核验利益点、行动或必要转场？

若没有损失，该段属于重复或填充。不得因为目标分钟数保留。

### 4. 时长真实性检查

先完成去重与删填充，再按目标音色实测；尚无目标音色时，仅给出多档语速估算。若真实内容短于目标时长：

- 不补通用酒知识；
- 不重复产品总结；
- 不重新解释前文术语；
- 不把规格核对和CTA扩成多个段落；
- 在运营稿标记 `insufficient_verified_material_for_target_duration`；
- 列出要达到目标时长所缺的事实、活动、产品或真实观众问题。

文件名和交付说明必须写真实支持时长，不能把短稿继续命名为已完成的30分钟稿。

### 5. Fresh draft重合检查

反馈重写后，与上一版检查连续长表达。允许保留：产品全名、产区、规格、法定提示和无法自然改写的事实。其他相同长句必须改写。审计报告至少记录：

```yaml
fresh_draft_from_original_sources: true
previous_draft_used_as_body: false
catalog_total_verified: false
nonessential_long_phrase_overlap: 0
duration_material_status: sufficient | insufficient_verified_material_for_target_duration
```

## 常见文笔问题

### 碎句化

症状：所有句子都很短，每两三句空一行，数字人像逐条念卡。

修正：长短句交替；多数句子可在10–36个中文字符；连续五个同结构短句必须合并；一个段落通常2–5句。

### FAQ拼接

症状：反复出现“有人会问、这款适合谁、为什么、当然不是”。

不推荐：

> 有人会问，圆润是不是没特点？当然不是。

推荐：

> PLUS的圆润不是寡淡。成熟果香在前，桶香收在后面，刚接触干红的人更容易接受。

### 泛化评价

集中检查：

```text
这款|可以|比较|适合|就是|有内容|比较稳|接得住|对路
```

这些词不是禁词，但密集出现时应换成具体味道、对象或使用结果。

### 产品模板重启

症状：每款都按“定位—工艺—闻香—入口—配餐—CTA”完全相同地展开。

修正：让不同产品承担不同叙事任务。例如，入门款围绕接受度，旗舰款围绕结构和宴请，礼盒款围绕对象与场合，日常款围绕餐桌便利。

### 过度文学化

文笔优化不等于增加比喻、辞藻和广告口号。判断应清楚，关键句可记住，但不能满篇“出生地、骨架、沙发、开窗、外套”。

## 机械报警指标

以下只触发复审，不代替人工判断：

- 相同句首出现4次以上；
- 连续5句都短于12个中文字符；
- 超过45字的句子未逐条复核；
- 单句段落占比过高；
- 问号和自问自答过密；
- 每款段落数量和顺序几乎相同；
- “有人会问”整轮超过2次；
- 纯口播含标题、时间轴、镜头或运营说明。

## 24小时循环复核

主播正文不得出现：

- 目标时长或“这半小时”；
- 早中晚问候和当前时段；
- “刚开播、马上结束、感谢观看、下次再见”；
- 一次性告别式收口。

结尾应回收选购逻辑，并自然回到第一款或任一循环入口。

## 交付报告建议字段

```markdown
- 主播人格一致性：PASS
- 整篇文笔重写：PASS
- 跨产品连续审校：PASS
- 碎句化与拼接感：PASS
- 重复句首与FAQ模板：PASS
- 解释必要性：PASS
- 常见名词硬解释：0
- 单句段落：0或已说明
- 超过45字句子：0或已逐条复核
- 首尾无缝循环：PASS
- 目标音色实测：PASS / 待执行
```
