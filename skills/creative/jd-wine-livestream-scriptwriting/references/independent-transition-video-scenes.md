# 转场商品视频的图层与场景映射

当酒类直播剧本将直接用于麦兔搭建，且用户要求“转场商品视频单独出来”时，先确认“单独”指独立图层还是独立 scene/clip。该短语本身不能证明用户要新增场景。

## 两种结构

### A. 主讲场景内的独立顶层视频图层

用户说“直接加到最上方”，或在某个产品主讲场景手动插入正确示例时，采用此模式：

- 保留原产品主讲 scene、数字人、脚本和原主讲视频；
- 额外新增一个转场商品视频图层，使用独立 `clip_material_id` 和清楚名称；
- 原主讲视频与转场视频可以使用同一 `material_id`，因为它们承担不同图层角色；不得按素材去重误删；
- 用户手动示范层是权威样本，先做 before/after working-room diff，再复刻到其他 SKU。

### B. 独立转场 scene/clip

只有用户明确要求新增场景，或既有结构清楚地把转场分成独立场景时采用：

- 每个转场拥有独立 scene/clip、场景名和素材身份；
- 转场口播文本单独保存，不与前后主讲稿混用；
- 独立场景不默认等于纯视频。仍需口播时必须保留数字人和唯一文本；只有用户明确要求纯视频时才删除。

两种模式都必须绑定正确 SKU 的整体、酒体、开箱或专用转场视频。不能把短时长的静态商品图动画仅因扩展名为 MP4/MOV 就当成合格转场视频。

### 麦兔顶层契约

```text
product_video  -> layer_n=1（最上方），x=0，y=0，w=1080，h=1920，fit=cover，sound_enabled=false
digital_human  -> layer_n=2（下方），保留 speaker_id 与 digital_human_image_id
script_text    -> 唯一口播文本
```

麦兔此处的图层方向与常见“数字越大越靠前”相反。视频覆盖数字人画面不影响数字人口播；若用户希望同时看见数字人，再把数字人改为明确的小窗前景布局。

同场景叠加时，目标通常是“一个原主讲视频 + 一个新增转场视频”。插入前后必须按 `clip_material_id` 计数；发现 3–4 个同源视频层时，保留原层和用户示范层，删除自动化误加副本。

## 搭建验收

最终回读必须同时证明：

1. 已按用户选择落地为独立图层或独立 scene，而不是代理自行改换结构；
2. 转场 video material 指向正确 SKU 和正确素材角色，真实 URL 为视频，时长合理；对疑似静态动画的候选，抽取第 1 秒与中段帧检查运动量；
3. 需要口播时，text material 唯一存在，数字人 material 同时存在，并具有有效的 `speaker_id` 与 `digital_human_image_id`；
4. 商品视频全屏、`layer_n=1`、原声关闭；数字人口播下层为 `layer_n=2`；
5. 同场景叠加时，原主讲视频与新增转场视频分别拥有独立 `clip_material_id`，同源视频数量符合设计；用户手动示范层未被删除；
6. 独立场景模式下，页面场景卡数量与 working-room 场景清单一致；
7. API mutation 后硬刷新可见页面，再次回读确认没有缓存回写或重复层；
8. `status=0`、`live_session_id=null`，未点击正式开播。

## 快速场景模板

三 SKU、十分钟可采用：

- SKU A 主讲：约 3 分钟；
- A→B 转场：约 30 秒，B 整体/开箱视频；
- SKU B 主讲：约 3 分钟；
- B→C 转场：约 30 秒，C 整体/开箱视频；
- SKU C 主讲与循环重入：约 3 分钟。

该模板只定义媒资与场景边界，不意味着可以用空泛内容凑时长；事实密度、成交力和循环直播约束仍按主技能执行。
